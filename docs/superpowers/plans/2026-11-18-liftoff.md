# Liftoff Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A menu-bar macOS app that, on the first weekday-morning unlock, walks Đại through a 9-step "pre-flight" with voice, music and CleanMyMac-style visuals in a notch panel (or fullscreen), auto-ticking steps the Mac can observe.

**Architecture:** Pure, unit-tested logic lives in `LiftoffCore` (config, trigger policy, day ledger, sequence state machine, line selection, device learning). `LiftoffSystem` adapts macOS (IOKit, CoreAudio, NSWorkspace, distributed notifications, AVAudioEngine, ElevenLabs, Keychain) into `SystemEvent`s and audio actions. The `Liftoff` executable is the SwiftUI/AppKit shell: a coordinator feeds events into `SequenceEngine` and renders its state in a notch panel or fullscreen window.

**Tech Stack:** Swift 6.3 (Command Line Tools, no Xcode), SwiftPM, SwiftUI + AppKit, Swift Testing, IOKit, CoreAudio, AVFoundation, ServiceManagement, Security (Keychain).

**Spec:** `docs/superpowers/specs/2026-11-18-liftoff-design.md`

## Global Constraints

- Platform floor `.macOS(.v14)`; target machine is macOS 26 on Apple Silicon with a notch.
- No Xcode: everything builds with `swift build`; tests run via `make test`, which passes `-F/-rpath` for `/Library/Developer/CommandLineTools/Library/Developer/Frameworks` and `-rpath` for `/Library/Developer/CommandLineTools/Library/Developer/usr/lib` (plain `swift test` fails with "no such module 'Testing'").
- App bundle id `com.daitran.liftoff`, `LSUIElement = true`, ad-hoc signed, installed to `~/Applications/Liftoff.app`.
- Data dir: `~/Library/Application Support/Liftoff/` containing `config.json`, `ledger.json`, `history.json`, `voices/`, `illustrations/`, `music/`.
- Trigger window default 08:00–10:30, Mon–Fri; "done for today" = completed **or** skipped.
- Voice addresses the user as "Commander"; female English voice; fallback `AVSpeechSynthesizer` preferring Zoe → Ava → Samantha (enhanced/premium first).
- Music ducks to 35 % while voice speaks; fades out over 3 s when Apple Music starts playing and stays off.
- No global hotkeys and no Accessibility permission; the notch panel only takes key focus after a click.
- Bundle ids: Teams `com.microsoft.teams2`, Music `com.apple.Music`, Agent Factory `dev.agentfactory.desktop` **or** process name "Agent Factory" (the `~/Applications` copy is an AppleScript applet without a bundle id).
- Step gradients (top → bottom hex), from spec §5.1: cables `#0f5c55,#0a2f3a`; dock `#5b6577,#232a38`; dac `#b3203a,#4a0a22`; agentFactory `#5c3bd6,#1d1450`; water `#2aa7d8,#0b3c63`; headphones `#3b3530,#0e0c0b`; music `#ff3b5c,#7a0f3a`; teams `#5059c9,#1f2259`; liftoff `#ffb35c,#d4466a,#3a1a5c`.
- Placeholder SFX until custom ones exist: chime `/System/Library/Sounds/Glass.aiff`, tick `Tink.aiff`, liftoff `Hero.aiff`. Music: first `.mp3`/`.m4a` in `music/`; none present → no background music, everything else works.

## Review Focus

1. Unlock at 10:31, on a Saturday, or a second unlock after finishing/skipping today → must stay silent (Task 2 tests).
2. K7 already on (or Teams already running) when its step begins → ticks immediately with the "already" line, never hangs (Task 3 tests).
3. No ElevenLabs key / offline / missing clip → system voice speaks the same line; no silence, no crash (Task 6 tests).
4. A device unplugged after its step ticked (e.g. monitor flickers) → step stays ticked; sequence never goes backwards (Task 3 tests).
5. Mac sleeps mid-sequence and is unlocked again the same morning → resumes at the saved step, not from the greeting (Task 2 + Task 3 tests).

### Task 3: Snapshot, rule evaluation and the sequence engine

**Files:**
- Create: `Sources/LiftoffCore/Snapshot.swift`, `RuleEvaluator.swift`, `SequenceEngine.swift`
- Test: `Tests/LiftoffCoreTests/RuleEvaluatorTests.swift`, `SequenceEngineTests.swift`

**Interfaces:**
- Consumes: Task 1 models.
- Produces:
  - `struct SystemSnapshot: Equatable { var devices: Set<DeviceSignature>; var runningApps: Set<RunningApp>; var musicPlaying: Bool? }`, `struct RunningApp: Hashable { bundleID: String?; name: String }`
  - `enum SystemEvent: Equatable { case snapshot(SystemSnapshot), appActivated(RunningApp), musicStateChanged(playing: Bool) }`
  - `struct EventLog { mutating func record(_ e: SystemEvent); func activated(_ m: AppMatch) -> Bool; var musicStartedPlaying: Bool }`
  - `func isSatisfied(_ step: StepDefinition, learned: [DeviceSignature], snapshot: SystemSnapshot, log: EventLog) -> Bool` — devices rule: learned non-empty → every learned signature matched by some snapshot device; else `hint` substring on a device of that kind; display with `hint == nil` and nothing learned → any `.display` device (snapshot only lists external displays); usb with no hint/learned → false. `.appActivated` also true if log has it. `.musicPlaying` → `snapshot.musicPlaying == true || log.musicStartedPlaying`. `.manual`/`.final` → false.
  - `struct LineKey: Hashable, Codable { step: StepID?; kind: Kind; enum Kind: String, Codable { greeting, greetingResume, prompt, confirm, already, liftoff } }`
  - `enum SFX: String { chime, tick, liftoff }`
  - `enum EngineAction: Equatable { case show(stepIndex: Int), say(LineKey), play(SFX), ticked(stepIndex: Int), handOffMusic, persist(DayLedger.Status), finished, dismissed }`
  - `struct SequenceEngine { init(config: LiftoffConfig, resumeAt: Int?); private(set) var currentIndex: Int?; private(set) var ticked: Set<Int>; private(set) var isFinished: Bool; mutating func start(_ s: SystemSnapshot) -> [EngineAction]; mutating func handle(_ e: SystemEvent) -> [EngineAction]; mutating func confirmManual() -> [EngineAction]; mutating func skipStep() -> [EngineAction]; mutating func skipAll() -> [EngineAction]; mutating func advance() -> [EngineAction] }`

Engine behaviour (the coordinator calls `advance()` after the confirm/already line finishes playing):
- `start`: fresh → `[.play(.chime), .say(greeting)]` then the first step's actions; resume → `say(greetingResume)` then step `resumeAt`.
- Entering step i: `[.show(i), .persist(.inProgress(i)), .play(.chime), .say(prompt)]`; if already satisfied → append `[.ticked(i), .play(.tick), .say(already)]`.
- Satisfied while waiting → `[.ticked(i), .play(.tick), .say(confirm)]`; music step also emits `.handOffMusic` (once per run).
- Once ticked, a step never un-ticks; events for other steps are only logged.
- Entering the `.final` step → `[.show(i), .play(.liftoff), .say(liftoff), .persist(.completed), .finished]`.
- `skipStep` → ticks current without confirm line, then caller advances. `skipAll` → `[.persist(.skipped), .dismissed]`.
